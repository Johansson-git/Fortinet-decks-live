How this is built

  • Every rule listed under a use case was read from the FortiSIEM 7.6.0 rule definitions (crawled 5 October 2026), including which event types it reads. A rule counts as covered when at least one source it accepts is collected.
  • Rates per user, per server and per tenant are estimates, not measurements. Low, Medium and High change rates, computers per user, server share and the burst factor. Measure the largest sources before quoting: process creation on servers and member-server logons.
  • Sizes are uncompressed bytes as received. Stored size depends on how FortiSIEM writes events, so replace the stored percentage with your sizing tool's per-event figure.
  • FortiGate authentication is listed under password spraying but never added to volume, because FortiGate logs are licensed separately.
  • The brute-force and spraying rules use FortiSIEM logon event-type groups. Their Windows members were checked in a 7.6.0 system (Device and Domain Logon Failure and Success); the Windows groups contain no Entra or Office 365 event types, while Entra sign-in success and failure belong to the Application Logon groups.
  • Sudden User Location Change has no log event types in its rule. It fires on an event from FortiSIEM's identity engine, whose inputs are the successful-logon events listed in /opt/phoenix/config/identityDef.xml, including Entra interactive sign-ins, Office 365 logins and VPN tunnel-up. The two Windows login-profile rules also fire on internal events; their inputs are assumed to be Windows logon events, which the public documentation does not confirm.
  • Use cases that depend on a product beyond FortiSIEM and native Windows, Entra and Microsoft 365 logs say so under Requires. Entra sign-in log export needs Entra ID P1, which is included in Microsoft 365 E3 and Business Premium.
  • The 3 new Linux ITDR rules are not part of these use cases.
